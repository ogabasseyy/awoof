**Public contracts:** Existing success wrapper remains `{ success: true, data, message? }`. POST /auth/student/register-request validates strict fields email, password, name, universityId, optional matricNumber, verificationConsent literal true and current noticeVersion. Return data `{ email, challengeId, expiresAt, resendAvailableAt }` only after successful transport. POST /auth/student/register-confirm requires those immutable identity/notice fields plus challengeId and six-digit otp; password is chosen/validated at confirmation and is not a pending identity claim. On success retain `{ user, tokens, redirectTo: '/marketplace' }`, adding authoritative `eligibility` to user data; do not use the permanent flag as proof. Both date fields serialize as ISO strings. Request cooldown/lock returns429 with retryAt and Retry-After; invalid/expired proof returns an explicit401/400 without exposing stored secrets; configuration/delivery failure returns503 with honest retry guidance, never raw provider diagnostics.

POST /auth/verify-student-email becomes an informational preflight: data `{ supported: boolean, reason?: string, verificationNotice: { version: string, text: string } }`, never `verified:true`, studentData, provider enrollment or account existence. Notice metadata comes from VERIFICATION_NOTICE_VERSION and VERIFICATION_NOTICE_TEXT and is present on every successful preflight response, including supported:false; infrastructure failures still fail. This additive metadata was Astra-approved during implementation to let unauthenticated clients display the current notice before collecting affirmative consent, without copying a separate notice into the frontend. Backend request/confirmation stale-version checks remain mandatory. Approved-domain support is not mailbox ownership. Inactive/missing school or unapproved exact domain is unsupported. Generic POST /auth/register with role student returns410 with the dedicated signup request path; vendor registration remains available and cannot accidentally be routed through student assurance.

Export a service factory with injected `isEmailConfigured(): boolean` and `deliverOtp(email, code, name): Promise<{success:boolean}>` for synthetic transport testing; default application instance uses the existing email module. No transport injection through HTTP. Its request method returns the public request data above. Its confirmation method returns an INTERNAL completion `{ user: { id, email, role: 'student' }, eligibility, expectedPasswordHash }` after commit; expectedPasswordHash is used only by the controller's durable session call and must never be serialized into a response or log. Only the controller issues the ordinary login session after service success/commit using this exact new identity. It constructs the explicit public response fields above and must never issue a session for an existing email selected from input.
